# 使用 Tailscale

在“配置 → 模块 → 新建模块 → Tailscale”中创建连接。默认连接 Tailscale，也可填写 Headscale 的 HTTPS 控制服务器地址。每个生效配置最多启用一个 Tailscale 模块；可放在全局或指定配置中。

新建时点“添加并登录”，内核启用连接后会自动打开浏览器登录页。之后展开模块，上半部分是即时生效的连接状态、登录/退出和设备列表，下半部分是需点“保存”的设置。主机名默认取本机名称，控制服务器在“高级”里。若显示“需要批准设备”，请在 tailnet 管理控制台批准。登录链接只在主动登录后打开，身份凭据保存在本机，不写进模块 YAML。

规则模式下，可见设备的 IP 和完整 MagicDNS 名称自动走 Tailscale。设备列表提供 IP、DNS 名称、在线状态和连接检查；检查结果（延迟、直连或中继）显示在设备行上。中继也是正常的连接方式。设备超过 8 台时才显示搜索框。

远端子网需要在模块里勾选并保存，开关旁注明发布它的设备；列表外的子网填在下方文本框，每行一个。例如 `192.168.50.0/24`。子网路由器还需要在 tailnet 中发布并获批这些路由，目标访问也必须被 ACL/grants 允许。路由器离线时，已选子网仍交给 Tailscale，连接失败不会退回本地直连。选定子网与本地 LAN 重叠时，经过内核的匹配流量优先访问远端。

流量必须先经过 ClashCube。系统代理的默认绕过列表包含私网地址，浏览器可能直接绕过；当绕过项覆盖 Tailscale 地址或已选子网时，模块里会提示并链接到绕过设置，也可通过现有入口启用 TUN。非规则模式下模块会提示并提供“切换到规则模式”。SSH 等不使用系统代理的程序需要 TUN 或显式 SOCKS5 代理。例如 macOS 的 `nc` 可用于 SSH 的 `ProxyCommand`：

```sh
ssh -o 'ProxyCommand=nc -X 5 -x 127.0.0.1:7890 %h %p' user@device.example-tail.ts.net
```

把端口换成自己的 mixed 端口、域名换成设备列表中的完整名称。本功能不会设置系统 DNS 搜索域，短主机名不保证可用。系统 `ping` 的 ICMP 不属于 TCP/UDP 代理通路，请用模块中的“检查连接”或实际服务确认连通性。

模块只管理出站访问，不提供 Exit Node、子网发布或本机服务入站。用户自定义规则和现有 STUN/QUIC 防护仍具有既定优先级。普通公网测速跳过 Tailscale，自动收集全部节点的策略组也排除托管连接。

重载配置、改模块显示名、改子网选择不会创建新身份。复制配置保留身份 ID；直接复制 Tailscale 模块不开放，以免重复启用。更改主机名或控制服务器后保存，会自动重启内核以释放旧连接。退出登录需再次点击确认，会调用 Tailscale Logout；停用或删除模块不删除身份目录，也不会在 tailnet 管理后台删除设备。

身份存放于 `<ClashCube 数据目录>/core/tailscale/<identity>/tailscaled.state`，禁止分享该目录。身份文件使用原子替换、仅所有者可读写，并由操作系统文件锁限制为单一 core 使用。在 macOS 提权 core 中创建的持久身份仍归 core home 的用户所有；SDK 辅助缓存按运行 uid 隔离，以便切换回普通 core。

实现说明：托管出站增加 `auto-route: true` 与 `route-prefixes`，`TAILSCALE` 规则读取实时 peer/MagicDNS 状态。规则在所有模块合并后加入，避免被应用分流的规则替换吞掉。内核仅在接受配置后激活连接；相同 state-dir 的配置世代共享 tsnet session，旧连接释放前不会出现第二个身份写入者。管理接口由现有随机 secret 认证，状态通过 core 的 NDJSON 流进入 `backend.State` 和既有 `state` 事件。

当前自动化验证涵盖真实 core/tsnet 启动与重载（本地模拟控制服务器）、状态事件、API 认证、身份文件互斥及持久化、DNS/规则动态更新，以及前端登录和子网保存边界。真实账号认证、跨设备 TCP/UDP、ACL、DERP 回退、普通/提权模式转换和 Windows 实机仍需在测试 tailnet 中验收。
