# MihomoBar 设计文档

> 版本：v0.1（首版，仅 macOS）
> 技术栈：Go 1.25+ · Wails v3 (beta.27) · React 18 + TypeScript + Vite · mihomo（`third_party/mihomo` 子模块，`Demogorgon314/mihomo@openconnect-support`）

## 1. 目标与范围

一个 macOS 的 mihomo 管理工具，有菜单栏面板和完整主窗口两套界面。mihomo 作为 Go 依赖从源码编进 app，不额外下载或打包预编译的内核二进制。

### 首版（v0.1）
| 模块 | 内容 |
|---|---|
| 内核 | 启动、停止、重启；启动前校验配置；崩溃检测 |
| 模式 | 规则、全局、直连 |
| 代理 | 代理组列表、切换节点、单节点/整组测速、按延迟排序 |
| 订阅 | 导入 URL 或本地 YAML、更新（单个/全部，可设自动更新间隔）、删除、切换当前配置 |
| 系统代理 | 开关，可配置绕过列表 |
| TUN | 开关，选择栈（system / gvisor / mixed / mips）；悬浮显示实现说明，选中项的说明显示在标题下；首次使用需授权 |
| 连接 | 实时列表、搜索、关闭单条或全部 |
| 规则 | 列表、搜索 |
| 日志 | 实时流、按级别过滤、搜索 |
| 概览 | 实时上下行速率与曲线、内存、连接数、累计流量 |
| 设置 | 端口、allow-lan、ipv6、日志级别、开机启动、主题、语言、Dock 图标 |

### 后续版本
- 全局快捷键
- 远程机器管理
- 应用自动更新
- Provider 管理页
- 配置编辑器

内核随 app 一起升级，不需要 ClashBar 那套单独更新内核的逻辑。

## 2. 总体架构

同一个可执行文件，三种运行模式：

```
MihomoBar.app/Contents/MacOS/mihomobar
│
├── (默认)  GUI 模式 ── Wails v3 应用：托盘面板 + 主窗口
│               │  只通过 REST/WS 调用内核，不直接访问 mihomo 的全局状态
│               ▼
├── core     内核模式 ── import mihomo，hub.Parse(runtime.yaml)
│               在 127.0.0.1:<端口> 提供 external-controller，用随机 secret 鉴权
│
└── helper   特权模式 ── root LaunchDaemon（只在用户开启 TUN 或授权系统代理后安装）
                负责以 root 身份拉起 core、设置系统代理；通过 unix socket 和 GUI 通信，并校验对端 uid
```

### 2.1 为什么内核要单独一个进程，而不是跑在 GUI 进程里
调研结论（详见第 9 节）：
1. mihomo 的状态都是包级单例：`executor.Shutdown()` 不会关闭端口监听和 REST 服务，`/restart` 会对宿主进程执行 `syscall.Exec`。
2. TUN 需要 root，而 WebView 进程不能以 root 运行。
3. 内核崩溃不能把 UI 一起带走。

所以 GUI 用 `os.Executable()` 加上 `core` 参数把自己拉起来作为内核进程。整个产物仍然只有一个二进制，mihomo 也仍然是从源码编译的 Go 依赖。

### 2.2 两种内核运行方式
| | 用户模式（默认） | 服务模式（开启 TUN 时） |
|---|---|---|
| 谁拉起 core | GUI 直接拉起子进程 | helper（root）拉起子进程 |
| core 身份 | 当前用户 | root |
| 是否支持 TUN | 否 | 是 |
| 系统代理怎么设 | `networksetup`（当前用户身份） | helper 用 SCPreferences / networksetup |
| 首次使用 | 无需授权 | osascript 弹一次管理员授权，安装 LaunchDaemon |

开启 TUN 时：helper 没装就先安装，然后让 helper 以 root 重新拉起 core，GUI 再重连控制接口。关闭 TUN 时 core 继续留在服务模式，避免来回切换。

### 2.3 控制接口与安全
- **core 控制接口**：`127.0.0.1:<空闲端口>`，secret 是每次启动随机生成的 32 字节。不用 mihomo 自带的 unix socket，因为它不校验 secret，而且文件权限是 0666；core 以 root 运行时，任何本地进程都能控制它。
- **helper 的 socket**：`/var/run/mihomobar-helper.sock`。每个连接都用 `getsockopt(LOCAL_PEERCRED)` 取出对端 uid，只放行安装时记录的 uid。这是对 ClashBar 的修正，它的 XPC helper 不校验调用方。
- **helper 的接口**：只做固定的几件事：`core.start(home, configPath)`、`core.stop`、`core.status`、`proxy.set/clear/get`、`version`。不执行任意命令。configPath 必须在安装用户的数据目录下。
- **残余风险**：root core 读取的是用户目录里的配置文件，所以以该用户身份运行的进程可以通过改配置影响 root core。所有 clash 类 GUI 的“服务模式”都有这个问题，在设置页的说明里写明。

## 3. 目录与文件布局

数据目录：`~/Library/Application Support/MihomoBar/`
```
settings.json          应用设置（主题、语言、当前配置、端口覆盖、开关状态等）
usage/<日期>.json      流量统计，一天一个文件，保留 90 天
modules.json           模块（叠在每个配置上的 YAML 片段），按顺序合并
profiles/
  index.json           订阅元数据（名称、URL、更新间隔、上次更新时间、流量/到期信息）
  <id>.yaml            每个配置一个文件
core/                  mihomo 的 home 目录（geo 数据库、cache.db、providers 等）
  runtime.yaml         实际交给 core 的配置（由“当前配置 + 应用覆盖项”生成）
logs/app.log
```

### 3.1 runtime 配置生成（相对 ClashBar 的改进）
服务分流模块中的固定节点名单优先生成 `proxies`：只直接引用当前配置顶层 `proxies` 中存在的节点，名称原样保留并去重。来自 `proxy-providers` 的节点和已失效的名字不能直接引用，仍通过 `include-all` 和精确匹配的 `filter` 查找；未匹配时拒绝连接。混合名单可同时生成 `proxies` 和 `filter`。按地区或关键词的选择仍使用动态筛选。当前配置没有任何勾选时生成 `proxies: [REJECT]`。转为 YAML 时也会读取当前配置及启用的普通 YAML 模块，以相同规则生成节点引用；转成普通 YAML 后，固定名单由用户维护。

ClashBar 是先启动 core、再用 `PATCH /configs` 补用户设置，中间有一段状态不一致的窗口期。我们改成启动前就把覆盖项合并好：
1. 读取当前配置的 YAML，解析成 `map[string]any`，未知字段原样保留。
2. 按顺序合并已启用的模块（`internal/modules`，参考 Surge 的模块）。模块是一段顶层为映射的 YAML，写法和 Clash Verge 的扩展配置一致：映射逐键深度合并，其他值直接替换；`+key` 把列表插到前面，`key+` 追加到后面，`key!` 连映射也整体替换；顶层的 `prepend-rules` / `append-rules`、`prepend-proxies` / `append-proxies`、`prepend-proxy-groups` / `append-proxy-groups` 作用于配置的规则、节点和策略组。模块在应用设置之前合并，所以端口、模式、TUN 开关和控制接口仍以应用为准，模块写了也会被覆盖。启用、修改或排序模块后照常 `core -t`：内核运行时热重载，停止时只校验；内核拒绝就恢复原来的模块（`TestModules`）。
3. 用应用设置覆盖这些键：`mixed-port`、`allow-lan`、`ipv6`、`log-level`、`mode`、`external-controller`、`secret`、`tun.enable/stack`，同时删除 `external-controller-unix`。
   设置页“防泄露”里的四个开关（默认都关）也在这一步生效：
   - **IPv6 流量进入 TUN**：TUN 开着而 IPv6 关闭时，顶层写 `ipv6: true`、`dns.ipv6: false`。原因是 mihomo 在 `ipv6: false` 时会去掉 TUN 的 IPv6 地址，而 auto-route 只给有 IPv6 地址的 TUN 加 IPv6 路由，IPv6 流量（WebRTC、路由器下发的 IPv6 DNS）就会绕过 TUN。core 启动时还会设 `SKIP_SYSTEM_IPV6_CHECK=1`，免得开机时没有 IPv6 的网络之后拿到 IPv6 时绕过 TUN。
   - **接管 DNS**：强制 `dns.enable`（配置里没有 DNS 段时补一个 fake-ip 的默认段），TUN 下覆盖 `dns-hijack` 为 `any:53`、`tcp://any:53`。
   - **拦截 UDP STUN**：规则最前面加 `AND,((NETWORK,UDP),(DST-PORT,3478/5349/19302-19309)),REJECT`。节点不支持 UDP 时 mihomo 会跳过该规则继续匹配，可能落到 DIRECT。
   - **DNS 查询遵循规则**：`dns.respect-rules: true`；没有 `proxy-server-nameserver` 时用 `nameserver` 补上（mihomo 要求）。
   只开系统代理、没开 TUN 时，这一节顶部提示 WebRTC 会暴露真实 IP，并提供“开启 TUN 和防泄露”（打开前两项再开 TUN）。
4. 写入 `core/runtime.yaml`（权限 0600），然后执行 `core -t` 校验，再启动或热重载（`PUT /configs?force=true {path}`）。

运行中切换模式、端口、开关时，先 `PATCH /configs` 立即生效，同时写回 settings.json，下次生成 runtime 配置时也会带上。

## 4. Go 代码结构

```

internal/
```

### 4.2 Wails 服务（前端通过自动生成的 TS 绑定调用）
| 服务 | 方法 |
|---|---|
| `AppService` | `State()`、`Start/Stop/Restart()`、`SetMode`、`SetSystemProxy`、`SetTun`、`ShowMain(view)`、`HidePanel`、`FitPanel(h, ms)`、`Quit` |
| `ProxyService` | `Groups()`、`Select(group, name)`、`TestLatency(kind, name)`（node/group/provider/all） |
| `ProfileService` | `List()`、`Import(url\|file)`、`Update(id)`、`UpdateAll()`、`Remove(id)`、`Use(id)`、`Reveal()` |
| `ConnService` | `Close(id)`、`CloseAll()` |
| `RuleService` | `Rules()` |
| `SettingsService` | `Get()`、`Patch(partial)` |

**事件（Go → 前端）**：
- `state`：内核状态、模式、开关
- `traffic`：每秒一次的上下行速率
- `memory`
- `connections`：只在连接页或概览页可见时订阅，减少开销
- `log`：只在日志页可见时订阅

前端通过 `Watch(topic, on)` 告诉 Go 当前需要哪些流，Go 侧按订阅情况打开或关闭对应的 mihomo WebSocket。

## 5. 界面设计

### 5.1 窗口
| 窗口 | 规格 |
|---|---|
| 托盘面板 | 宽 440pt，高度跟随内容，范围 220–560；无边框、半透明背景（`MacBackdropTranslucent`）、圆角 12；失焦或按 Esc 自动隐藏；`AttachWindow(...).WindowOffset(6)`；高度变化走原生动画，与 CSS 使用同一条贝塞尔曲线 |
| 主窗口 | 默认 860×600，最小 640×440，记住上次大小；`MacTitleBarHiddenInset`；页面顶栏可拖动，左侧留 96px 给红绿灯按钮；点关闭只隐藏，全屏时先退出全屏再隐藏；启用 `MoveToActiveSpace` |
| Dock 图标 | `LSUIElement`；可在设置里选：始终显示 / 不显示 / 主窗口打开时显示 |

### 5.2 主窗口布局
- **顶栏（50px）**：
  - 左侧：logo 和名称。
  - 中间：分段 Tab，只有一个滑动的高亮块，没有灰色底轨。Tab 依次是：概览、代理、配置、连接、规则、日志。
  - 右侧：内核状态胶囊（运行中显示绿点，停止显示灰点，出错显示红点）、模式切换、设置按钮（26px 图标按钮）。
- **内容区**：页面进入时淡入并上移 5px（`view-in .24s`）。内容是圆角 12 的卡片列表 `.list`，每行 `.row` 高 48，行与行之间用细分割线。
- **概览**：
  - 第一行：流量卡片：上下行速率、曲线（上下行两条线，60 秒滑动窗口，零值沉到底线以下，只留一条淡底线和两条虚线网格），底部一条统计栏：累计上传、累计下载、活跃连接数、内存。
  - 第二行：“网络”小标题（右侧是重新测量按钮）和四张连通性卡片：路由器、DNS、互联网、代理。延迟值右侧是最近测量的小柱状图：backend 为每项保留最近 30 次（不论是概览还是托盘发起的测量，经 `connectivity` 事件推送），最新在右、按延迟着色、历史半透明；失败画满高的淡红柱；纵轴取最大值但不低于每项的下限（路由器 5ms、DNS 50ms、其余 200ms），稳定时就是平的；换网后的第一根前面有一条细竖线。
  - 第三行：控制列表：出站模式（行内小号分段控件，副标题说明当前模式）、系统代理、TUN、当前配置。开关打开时左侧图标块变为主题色。
  - 概览页顶栏不再重复显示实时速率；状态胶囊带状态点（运行绿、过渡琥珀闪烁、出错红、停止灰）。
- **代理**：每个代理组一张卡片。卡片头显示组名、类型、当前节点和测速按钮；可以折叠展开，展开动画用 grid-rows 过渡，各行依次错开出现。节点以网格排列（名称加延迟胶囊），选中的节点用 `--sel` 背景色标出。延迟颜色：小于 200ms 绿色，小于 500ms 琥珀色，更高为红色，超时为灰色。
- **配置**：配置列表，当前使用的配置有标记。每行显示名称、来源（URL 或本地）、流量用量进度条、到期时间、上次更新时间。行内操作：更新、更多菜单（复制链接、在 Finder 中显示、删除），删除需要二次确认。顶部有“导入”按钮，点开是一个从按钮位置展开的弹出层，里面输入 URL 或选择本地文件。
- **模块**：配置页头部的分段控件切换“配置 / 模块”（`profiles#modules` 直接打开）。每个模块一行：名称、下面一行等宽字体列出它设置的顶层键（如 `dns · prepend-rules`）、上移 / 下移、删除（再点一次确认）和开关；关闭的模块名称变淡。点一行在原地展开编辑区（`Fold`）：名称和 YAML 文本框（Tab 插入两个空格，⌘S 保存，Esc 取消），空白时的占位文字是一个示例。输入停下 250ms 后由 Go 解析，YAML 有误或顶层不是映射时在下方红字提示，保存按钮不可用。“新建模块”弹出现成模块的菜单（名称和一句说明，已加过的标“已添加”），最后一项是“空白模块…”。现成模块（`modules.Templates`：局域网和 Apple 服务直连、国内网站用国内 DNS、屏蔽广告、嗅探域名、自定义 Hosts）点一下不会直接加入，而是在列表上方展开编辑区，名称和内容已填好、聚焦到内容，看过或改过后按“添加”才加入，新行闪一下。没有模块时，页面本身就列出这些现成模块，每个带“添加…”，下面是“空白模块…”。每个现成模块都由测试交给内核校验（`TestModuleTemplates`）。菜单的第二组是“服务分流”（`modules.Services`：Google、YouTube、OpenAI、Telegram）。点一个打开的不是 YAML，而是一个小表单。“走”是 `Segmented`（手动选择 / 自动选最快 / 直连）。“节点”也是 `Segmented`：全部节点 / 按地区 / 指定节点。按地区时是一排地区芯片（香港、台湾、日本、新加坡、美国），每个芯片后面是当前配置里匹配到的节点数，为 0 的变淡。指定节点时列出当前配置的全部节点（`RouteNodes`，含订阅里的节点），可以搜索、勾选。勾选只对当前配置生效，每个配置各选各的：节点名属于某一个订阅，所以名单按配置 ID 存。下面是“或名称包含”的关键词（输入后回车变成一个标签），对所有配置生效。被关键词匹配到的节点自动勾上、变淡、标“关键词匹配”。勾过、但当前配置里已经没有的节点（改名或下架）排在最后，标“已不存在”。从地区切到指定节点时，这个地区的节点先全部勾上，方便去掉不想用的。复制配置时连同名单一起复制，删除配置时清掉它的名单。这种模块存的是 `route`（服务、策略、地区，或按配置分开的节点名单加关键词），不是 YAML。模块本身仍是全局的，叠加到每个配置上。`runtimecfg.Build` 按每个配置重新生成 YAML，只取这个配置的名单：规则放到最前面，再追加一个 `include-all` 的策略组，按地区或关键词时用 `filter` 选节点，固定名单优先用 `proxies`（provider 节点仍精确筛选，见 §3.1）。需要筛选的勾选名字整个匹配（转义，反引号写成 `\x60`，因为 mihomo 用反引号分隔多个 filter），关键词不分大小写、部分匹配。组设了 `empty-fallback: REJECT`：范围里一个节点都没有时，连接被拒绝，不会悄悄直连。指定节点却没给当前配置勾选、也没有关键词时同样拒绝，不会退回全部节点（生成 `proxies: [REJECT]`）。配置里已经有同名的组时，这个组改名为 `名称 (MihomoBar)`。加入以后，这一行的副标题写着“手动选择 · 香港”或“手动选择 · 指定 3 项”，右侧显示当前节点和延迟，点一下弹出节点菜单（`Popover`）直接切换；自动选最快的只显示、不能点；没有节点时显示红色的“没有节点”；如果是当前配置还没勾选，显示“为当前配置选节点”，点一下打开编辑区。代理页上这个组带“模块”标记。编辑区的“以 YAML 编辑”把它转成普通模块，保存后才生效。开关、排序、删除和保存都交给内核校验，被拒绝时列表恢复原样并提示内核的错误。
- **AI 服务分流预置**：OpenAI 包含 `geosite:openai`、`ai.com` 和 ChatGPT 进程；Claude 包含内置核心域名、`geosite:anthropic`、Claude 桌面/CLI 进程、共享遥测域名/关键词及 Anthropic IP/ASN；AI 服务包含 `geosite:category-ai-chat-!cn` 和 GrowthBook。三个预置默认手动选择美国节点，可在表单改地区或指定节点，空组拒绝连接。Claude 的共享遥测规则也会匹配其他应用使用这些服务的流量。它们只提供服务分流，不附带 DNS 或 UDP 拦截策略。模块按列表从上到下合并，每个模块的规则前插，所以同时使用时应把 AI 服务放在 OpenAI、Claude 上方，让后合并的专用规则优先于通用 AI 分类。
- **可编辑副本**：订阅的“更多”菜单有“创建可编辑副本”，复制为本地配置“<名称>（副本）”；复制的是正在使用的配置时直接切到副本，提示“已切换到…，可以随意编辑”。对订阅点“在编辑器中打开”会提示更新时修改会被覆盖，建议副本或模块。
- **外部编辑**：正在使用的配置文件被修改（如在编辑器里保存）后，每 3 秒的轮询发现修改时间或大小变化，就热重载；内核拒绝时保留正在运行的配置（`runtime.yaml` 也恢复为它），记一条错误事件并通知，同一份内容不再重试（`TestEditedProfileReloads`）。
- **Clash 导入链接**：兼容 `clash://install-config?url=<URI 编码的订阅地址>&name=<可选名称>`，也接受相同格式的 `clashmeta://` 链接。macOS 唤起应用后进入配置页并预填现有导入表单；确认前不下载，导入后不自动切换配置。冷启动的链接保留到主窗口就绪，连续收到的不同链接按顺序确认，同一待处理请求去重（包括通过两个协议收到的同一请求）。只接受 HTTP(S) 订阅地址，解析失败的提示不包含原始地址。应用包声明 `clash` 和 `clashmeta` URL Scheme，不主动修改系统默认处理应用。
- **连接**：保留进程／Host／规则分组和侧栏详情，提供活跃／已关闭／全部、暂停画面、时间／Host／速率／上下行速度／累计流量排序。搜索按空格分词并匹配所有词，覆盖源地址和端口、目标、嗅探域名、进程及代理链；关闭操作只提交当前结果中活跃连接的 ID，失败的连接保留并可重试。上下行速度和累计流量分别展示。主窗口持续串行采样，即使切换页面或暂停画面仍记录最近 500 条已结束连接；切换配置清空历史。历史为会话内存数据，结束时间和流量是最近采样估计，采样间隔内完成的短连接可能无法记录。
- **连接检查**：来源设备支持按 IP 多选筛选，设备备注保存在本机界面的 localStorage，备注也参与搜索；清空选择表示全部来源。进程分组、连接行和详情显示 macOS 应用图标，应用内的 helper 使用所属 `.app` 图标，内部流量使用 MihomoBar Logo，无路径时使用网络图标。详情补充连接 ID、嗅探域名、远端地址、入站和 DNS 模式，支持查看和复制内核原始 JSON（保留未建模字段，历史连接使用最后一次采样）。超过 200 条结果时将分组头和展开的连接行一起虚拟滚动，较短列表保留 Fold 动画。
- **连接显示偏好**：分组方式、协议筛选、排序字段及方向保存在本机 localStorage，重新打开页面或应用时恢复；搜索、暂停和来源选择只在当前页面有效。设备分组以来源 IP 为身份，标题显示备注与 IP，汇总当前匹配结果的连接数、上下行速度和累计流量；相同备注不合并设备。详情只滚动内容，头部、切换栏和底部操作固定可见；每个字段有复制按钮，支持复制全部可见详情文本或内核原始 JSON。
- **连接页工具栏**：只有一行：标题和计数、搜索、活跃／已关闭／全部、“筛选”（协议和来源设备，按钮上显示生效的筛选数）、“视图”（分组方式和显示列）、暂停、关闭匹配的连接（超过一条时要再点一次确认，3 秒后复原；确认只关闭第一次点击时的那批连接，修改搜索、筛选或切换标签会取消确认）。排序只在列头上点。
- **连接表格**：表头、分组和连接行在同一张卡片里。分组头是吸顶的分节行；只有一组时不显示分组头。行高 44px，数字列右对齐；速率为 0 和累计为 0 时显示淡色“—”。默认列把上下行速度合成一列“速率”，上行和下行分别用 `--up`、`--down` 色，只显示不为 0 的方向。代理链列把最终出口画成胶囊（DIRECT 绿、REJECT 红、其他强调色），前面是淡色的策略组路径。关闭按钮只在悬停或选中的行上出现。新连接淡入并短暂高亮；活跃页里刚结束的连接再留一个采样周期，变淡后移除；内核停止时直接移除。按速率排序时，指针在表格上就暂停因新采样引起的重排，新连接排在后面，移开后再按速率重排；点列头切换排序立即生效。
- **连接页键盘**：⌘F 聚焦搜索（Esc 先清空再失焦），↑／↓ 移动选中并滚到可见处，Esc 关闭详情，⌫ 关闭选中的连接，空格暂停或继续。空状态分三种：内核未运行时给出“启动内核”，有筛选时给出“清除筛选”，其余显示没有连接。
- **连接列布局**：显示列菜单可选择进程、来源、协议、规则、代理链、速率、上下行速度、累计上传／下载／总量和开始时间；目标 Host 始终显示。列头点击排序，再次点击反向；开始时间列同时显示持续时长。拖动列头边缘或聚焦分隔线后按左右键调整列宽，松开时保存；显示列和宽度随其他显示偏好持久化，可单独恢复默认列布局。列头与分组／虚拟列表共用列宽及横向滚动，窄窗口保留各列可读宽度，通过横向滚动访问全部信息。
- **规则**：上方是“我的规则”（用户规则，可添加、删除、上下移动），下方是内核当前生效的全部规则（搜索、按命中次数排序）。
- **规则集**：规则页顶部的分段控件切换“规则 / 规则集”（`rules#providers` 直接打开规则集）。每行显示名称、行为（域名 / IP 段 / 混合规则）、格式、条数、来源（远程 / 本地文件 / 内联），以及在 RULE-SET 规则里指向的策略；没有被任何规则引用的显示“未使用”。远程规则集可以单独更新或全部更新；更新失败时内核保留原有内容，界面提示失败的名称。内联规则集写在配置里，没有更新按钮。
- **查询**：规则页的第三个分段（`rules#lookup`）。输入域名、IP、host:port 或网址（默认端口 443），显示：命中的规则、路线（策略 → 节点）、内核实际连接的地址，以及解析结果（CNAME、A/AAAA 和 TTL）。路线的查法是经混合端口对目标发一个 CONNECT，读出内核给这条连接的规则和链路后立即关闭，不发送任何数据；被 REJECT 的目标显示 REJECT。配置启用了 DNS 时，用内核的 `/dns/query` 解析（拿到的是真实地址，fake-ip 模式下也是）；没启用时用系统解析器，并标为“DNS（系统）”。实际连接地址落在 fake-ip 段时提示：有别的 fake-ip 解析器（其他 TUN 应用或路由器）替本机作了解析。结果卡片上有“添加规则…”，推荐 DOMAIN / DOMAIN-SUFFIX（IP 则是 IP-CIDR）。
- **用户规则**：保存在数据目录的 `rules.json`，不写进订阅文件。`runtimecfg.Build` 把它们放在配置自带规则之前，所以优先匹配，更新订阅后也不会丢。策略名在当前配置里不存在的规则（在别的配置下添加的）会被跳过，不会让整个配置校验失败。添加或修改后立即热重载；内核拒绝新规则时恢复原来的规则。类型限定为一组只带一个值的类型（DOMAIN、DOMAIN-SUFFIX、IP-CIDR、PROCESS-NAME 等），值和策略里不允许出现逗号和换行，防止注入额外字段或规则。连接页右键菜单和详情栏都有“添加规则…”，会从连接推荐域名、域名后缀、IP 和进程名几种写法。点击“我的规则”中的一行可以编辑。进程类规则（PROCESS-NAME / PROCESS-PATH / PROCESS-PATH-REGEX）的值旁有“选择…”：列出连接里出现过的进程（排在前面）和正在运行的应用（不含 /System 下的系统应用，应用内的辅助进程归到所属 .app），也可以用“选择应用…”从磁盘选一个 .app 或可执行文件。选中后按类型生成值：PROCESS-NAME 取可执行文件名，PROCESS-PATH 取完整路径，PROCESS-PATH-REGEX 对 .app 生成 `^<应用路径>/`，可覆盖该应用的所有辅助进程。由选择器生成的路径规则在列表里显示为应用图标和名称。
- **事件**：在日志页头部用分段控件切换（日志 / 事件），不单独占用顶栏 Tab。内容是本次运行的事件，最新在上（最多 200 条，内存中）：内核异常退出、网络切换、睡眠唤醒、网络重置、自动组（URLTest / Fallback / Smart）切换节点、订阅更新失败或更新后校验失败、系统代理被改写。可只看警告和错误，可清空。
- **流量统计**：概览页头部用分段控件切换（概览 / 流量统计，`usage#week`、`usage#month` 直接打开对应范围），参考 Surge 的 Traffic Statistics。顶部卡片是所选时段的总量（大号）、上传、下载、连接数，下面是柱状图：“日”按小时 24 根，“7 天 / 30 天”按天；每根柱子下段为上传（`--up`）、上段为下载（`--down`），悬停显示该时段的数值。点“日”视图的某一小时，下方列表只看该小时（标题旁出现可清除的小时胶囊）；点 7 / 30 天里的某一天，切到那一天。‹ › 前后翻页，“今天”回到当前。下方按应用 / 主机 / 策略 / 网络分列：图标、名称、占最大项的比例条、上传、下载、总量和占比、连接数；先显示 50 条。“清空”需要再点一次确认。
  - 采集在 GUI 侧（`backend/usage.go`）：内核运行期间每 2 秒取一次 `/connections`，按连接 ID 求差得到每个应用（同 `appOf`，.app 内的辅助进程归到所属应用）、主机（嗅探域名 → host → 目标 IP）、策略（代理链的最终出口）的增量；总量用内核的 `uploadTotal/downloadTotal` 差值，所以一定准确。两次采样之间开始又结束的短连接，靠 `internal/core` 注册的 `/mihomobar/closed`（fork 中 `statistic.Manager.OnLeave` 回调）拿到最终字节数补上；没有该接口的旧内核（未更新的 helper）只是少了这部分。网络维度按当前 Wi-Fi 名称 / 有线 / 未连接归类。
  - 存储（`internal/usage`）：数据目录 `usage/<YYYY-MM-DD>.json`，一天一个文件，只改写当天的；每分钟和内核停止、退出时写盘。每天每个维度保留流量最大的 200 项，按小时记录分布；保留 90 天。

  - 增强模式（`tun`）：服务模式状态与卸载、栈、ICMP 转发，以及防泄露。
  - 内核：顶部是状态行（状态点、版本、运行身份、端口，启动/重启/停止；崩溃时显示错误和“查看日志”），下面是日志级别、清 DNS 缓存（连同 fake-ip 池）、更新 GEO（显示上次更新时间；等待下载完成，不受 15 秒超时限制，已有更新在进行时提示而非报错）、复制终端代理命令、打开数据目录。按钮执行中转圈并禁用，成功提示写明做了什么；内核未运行时说明原因。
  - 会让内核重载的设置，重载期间该行显示“正在应用…”；内核拒绝时设置回滚到原值，并提示“未生效”。

## 6. 关键流程

**启动**
1. 加载 settings。
2. 生成 runtime.yaml。
3. 执行 `core -t` 校验。
4. 拉起 core：用户模式由 GUI 直接拉起；如果上次是服务模式且 helper 可用，交给 helper 拉起。
5. 轮询 `/version`，就绪后打开 WebSocket 流。
6. 恢复系统代理状态。
7. 后台刷新 provider，并对所有组测一次速。

**退出**：关闭系统代理（如果是本应用开启的），停止 core（先 SIGTERM，2 秒后 SIGKILL）。服务模式下通知 helper 停止 core。

**崩溃**：core 意外退出时，状态变为 `crashed`，并显示最后 50 行输出；3 秒后自动重启一次，再次失败就停止并提示。

**系统代理**：设置所有已启用网络服务的 web、secureweb、socks 代理，加上绕过列表。退出或 core 停止时清除。启动时如果发现系统代理指向我们的端口，但 core 没有运行，就先清理掉。

## 9. 调研记录（摘要）
- **作为库调用**：实测`hub.Parse(bytes)` 加 `/version` 正常，同一进程内连续加载两次也正常。带 gvisor 的二进制约 60MB。
- **cgo**：darwin 上只有 `tailscale/certstore` 用到 cgo，关掉 cgo 时有替代实现；openconnect 不用 cgo。
- **`replace` 不会被依赖方继承**：使用方必须复制那 5 条，否则 `go mod tidy` 报 `unknown revision`。
- **`init()` 副作用**：logrus 默认输出到 stdout；`statistic` 包会启动一个 1s ticker；系统 DNS 兜底为 114/8.8.8.8。GUI 和 core 是同一个二进制，所以 GUI 进程也会执行这些 init()。不过它们只是一个空转的 ticker 和几个全局变量，影响可以忽略；GUI 从不调用 hub/executor。
- **ClashBar 可借鉴的点**：先 `-t` 校验再启动；订阅下载使用 `clash.meta` UA；网络恢复后自动重启 core；按标签页的可见性和前后台状态调整轮询和 WebSocket 订阅。

## 10. 交互逻辑参考 Surge for Mac

调研来源：manual.nssurge.com、kb.nssurge.com（release notes）。Surge 的菜单项都在官方资料中能找到，但官方没有公开菜单的排列顺序，下面的顺序按 Surge 5/6 的实际使用整理。

### 10.1 采纳的概念
- **出站模式**（Direct / Global / Rule）是凌驾于规则之上的全局开关，与 mihomo 的 `mode` 一一对应。主窗口和托盘都把它放在最显眼的位置。
- **系统代理**与**增强模式（TUN）**是两个独立开关，可以同时开启。图标状态要反映“当前是否真的在接管流量”。
- **代理组延迟**取当前选中成员的延迟；测速结果可以排序；HTTPS 测速不计入 TLS 握手时间（mihomo `unified-delay` 已经支持）。
- **手动测速**对齐 zashboard 默认 Dashboard 模式：页面、面板和原生菜单统一使用设置中的全局测速 URL；Go 后端共享 5 个请求槽位并合并重复的在途请求。单节点测试跟随嵌套组当前选中的节点，超时 5 秒；Selector、LoadBalance、Smart 组和 Provider 逐节点测试，超时 2 秒；其他组调用核心整组测速接口，超时 5 秒，以更新核心的健康状态和自动选择。“全部测速”覆盖核心和 Provider 的非组节点，按名称去重，排除 Reject、RejectDrop 和 Block，不受当前搜索过滤影响。`proxy-latency` 事件同步进度和逐节点结果，结束后各界面重新获取核心数据。未提供独立测速 URL 模式。
- **托管配置不可编辑，新配置不合法就不加载**：我们已经做到“更新后先 `core -t` 校验，失败就保留旧配置”。

### 10.2 托盘：左键面板 + 右键原生菜单
左键打开面板（第 5.3 节），右键弹出 Surge 风格的原生菜单，顺序如下：
1. 内核没在运行时才有状态行（已停止 / 正在启动 / 异常退出）；运行中的状态由图标表达（第 10.3 节）
2. 显示主窗口 ⌘M
3. “出站模式”子菜单（三个单选项），右侧用强调色徽标显示模式字母 R / G / D，和托盘图标一致
4. 每个代理组一个子菜单：组名在左，当前成员在右（灰色、右对齐）；子菜单第一项是“测速”，下面是节点：当前成员前打 ✓，延迟是右侧的彩色徽标。所有组之后是“全部测速”。点“测速”或“全部测速”不会关闭菜单，节点先显示“···”，结果出来后原地换成延迟
5. 连通质量：右侧徽标显示经代理（直连模式下为直连）的延迟，按延迟着色。菜单打开时如果结果超过 30 秒就重测；内核启动、切换模式或配置后也会测一次
6. 活跃应用：固定 5 行，按当前速率排序，显示应用图标、名称和速率，空行显示“—”。同一个 .app 里的辅助进程算作该应用。只在菜单打开期间每秒采样 `/connections`，数字实时更新；点击打开连接页
7. 仪表盘… ⌘D（打开连接页）
8. 设置为系统代理 ⌘S / 增强模式 (TUN) ⌘E
9. “配置”子菜单（右侧显示当前配置；✓ 标出当前配置，点击即切换）、更新全部订阅；复制终端代理命令
10. 启动 / 重启 / 停止内核
11. 退出 ⌘Q

AppKit 原生菜单项会在标题和子菜单箭头之间留出很宽的空隙，快捷键也要单独占一列，排不出 Surge 那样的紧凑布局。所以 `traymenu_darwin.go` 给每个菜单项都配一个自绘视图（`MBRowView`），自己画勾选标记、应用图标、标题、右侧的灰色文字或徽标，以及子菜单箭头，悬停高亮也自己画；点击时先关闭菜单，再触发菜单项原本的动作。Go 这边只在 Wails 菜单项的标题里加几个标记，表示右侧文字、徽标和图标。快捷键当作右侧文字显示（“⌘ M”），真正的快捷键挂在一个隐藏的同名菜单项上（`allowsKeyEquivalentWhenHidden`）。行高 22pt。菜单打开期间不整体重建，只原地更新连通质量和活跃应用两部分；期间的其他变化等菜单关闭后再重建。

### 10.3 图标状态
- 内核未运行：图标半透明、只有描边。
- 内核运行中，但系统代理和 TUN 都没开（没有流量被接管）：同样显示描边图标。这一点学 Surge，提醒用户“其实没生效”。
- 正在接管流量：实心图标。可选在图标旁显示速率（设置“在菜单栏显示速率”）。
- 系统代理被其他应用改写：`backend/watch.go` 每 3 秒用 `scutil --proxy` 看当前生效的代理，连续两次不是我们的端口就判定被改写。此后不再认为它归我们管（退出时不会清掉别人的设置），图标变为描边，概览和面板提示“重新接管”，记一条事件并发通知。

### 10.3.1 网络变化与唤醒
同一个轮询还会读 `State:/Network/Global/IPv4` 的主接口和路由器（TUN 的 utun 换成底下的物理接口），变化即视为换网。唤醒来自 `SystemDidWake`，以及墙钟跳变超过 30 秒。两者合并防抖 2 秒后重置网络：清 DNS 缓存（含 fake-ip）、关闭所有连接（它们绑在旧网络上，否则要等超时）；如果系统代理归我们但在新网络服务上没生效，就重新设置。重置后托盘和概览的连通性立即重测。

### 10.3.2 通知
第一次要发通知时才向 `UNUserNotificationCenter` 请求授权。macOS 只接受 Applications 文件夹（`~/Applications` 或 `/Applications`）里的 app 请求授权，与签名无关：ad-hoc 签名的 app 放在那里会正常弹出授权框；放在仓库的 `bin/` 或 `/tmp` 下，即使用 Apple Development 证书签名，也会被直接拒绝（不弹框，返回 “Notifications are not allowed for this application”）。所以用 `wails3 task install` 把 app 装到 `~/Applications`。被拒绝时，以及没有 bundle id 的裸二进制，都改用 `osascript` 的 `display notification` 发送：标题和正文作为参数传入，不拼进脚本；通知以“脚本编辑器”的名义发出，点击不会打开本 app。设置“通知”可关闭。只有内核异常退出、订阅更新失败、更新后校验失败、系统代理被改写、网络规则应用（成功或失败）这几类事件会发通知；原生通知点击后打开事件页。

### 10.3.3 网络规则与省流量
需求不是“按 SSID 换配置”，而是“在某个网络下流量该怎么走”：家里或公司不接管、公司内网直连而外面走某个节点、不同网络用不同订阅。Surge 也是在同一配置里按网络做条件（`SUBNET` 规则、Subnet Group、`[SSID Setting]`），而不是换配置。所以这里做成一组「网络 → 动作」的规则，存在 app 设置里（`settings.NetworkRules`），不写进 profile，订阅更新不影响它。

**条件**：Wi-Fi 的完整 SSID（区分大小写、保留空格，1–32 字节）、“有线网络”（主接口不是 Wi-Fi 接口：以太网、USB / 雷雳网卡）、“其他网络”（兜底，恰好一条，不可删除）。匹配顺序：已连接 Wi-Fi 的 SSID 规则 → 主接口为有线时的有线规则 → 其他网络。同时连着有线和 Wi-Fi 时，SSID 规则优先。

**动作**（都可选，不设即“不更改”）：配置、出站模式、系统代理、增强模式 (TUN)、若干 Selector 组的成员。应用顺序：配置（热重载，先 `core -t`）→ 代理组 → 出站模式 → 系统代理 → TUN。某一步失败记一条警告事件，其余照做；全部成功且有改动时记一条信息事件。两者都发通知（设置“通知”可关闭）。内核停止时不启动内核，只改设置；代理组在内核启动或换配置后再选一次。TUN 只在 helper 已安装且是当前版本时才开，绝不弹密码框，否则记警告跳过。

**确定性**：其他网络是基准。任何规则设了某项，保存时若其他网络没设这一项，就自动补上（布尔取反、模式补“规则”、配置补当前配置、代理组补当前成员），编辑其他网络时这些项不能选“不更改”。这样状态只由当前网络决定：离开公司一定回到基准，不会因为“未匹配保留当前”而带着公司的直连去咖啡馆。

**换网与手动更改**：复用每 3 秒的网络轮询，网络身份是 SSID 加主接口和路由器，连续两次相同才算稳定；稳定到新身份时清掉手动更改并应用规则。SSID 暂时不可读不算换网；断线（离线两次）再连同一网络算新连接。手动改出站模式、系统代理、TUN、配置或代理组成员时，若当前规则管理这一项，就记为该项的手动更改（按字段，其余项仍跟随规则）；改回规则的值即恢复跟随。手动更改持续到换网、点“恢复规则”、编辑规则或重新开启功能。设置页、面板和托盘菜单显示当前网络、生效的规则和被手动更改的项，并提供“恢复规则”。

**界面**：设置页“网络规则”一节：总开关（即时生效）；当前网络行（网络名、生效规则、手动更改、定位权限按钮、“为此网络添加规则…”）；规则列表，每行一条摘要，点开在 Popover 里编辑，`×` 删除；“添加网络…”。编辑弹层：条件（Wi-Fi / 有线），SSID 输入框下列出当前 Wi-Fi 和系统记住的网络（CoreWLAN `configuration.networkProfiles`，排除已有规则的名称），名称重复或过长直接在弹层里提示；五类动作。删除了的配置显示“配置已删除”，不妨碍编辑其他规则。

**权限**：通过 CoreWLAN 读当前 Wi-Fi，不扫描、不改网络。读 SSID 需要定位权限，只在用户点“允许访问”时向 CoreLocation 请求，不采集坐标；应用包提供定位权限说明。没有权限时 Wi-Fi 网络只能匹配到其他网络，有线和其他网络规则不受影响。裸开发二进制可能无法正常请求权限，应使用 app 包验证授权流程。

**省流量**：不做成规则，而跟随系统标记：`NWPathMonitor`（排除 utun，看 TUN 下面的物理网络）报告 `isExpensive`（个人热点）或 `isConstrained`（低数据模式）时，且设置“在计费网络上省流量”打开（默认开），暂停订阅自动更新（到不计费的网络再补）、托盘连通质量的自动测量（打开菜单时仍测）和概览卡片的 30 秒定时测量。核心自己的健康检查和 provider 更新不在此列。
