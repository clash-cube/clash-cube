# 设备固定出口与断网保护：设计方案

状态：首版已实现并部署到隔离 Docker QWRT 环境，入口为 LuCI → ClashCube → 设备。[交互原型](prototypes/device-egress.html) 仍使用示例数据。具体实现、限制及测试命令见 [OpenWrt 文档](openwrt.md#device-fixed-egress-and-persistent-protection)。本文的后续阶段不代表均已开放。

首版包括设备发现/手动填写、可选 DHCP 静态租约、固定远程节点、独立的保护/联网状态、暂停/恢复、更换节点、带确认的解除保护、独立开机 guard、IPv4 TCP 与专属 DNS，以及其他外网 UDP/IPv6 阻断。最多保护 32 台设备。TPROXY UDP、策略组/复杂拨号链、独立 SSID/VLAN 和实际公网出口 IP 核验仍属于后续范围；当前验证不代表其他固件或硬件流量分载已通过验收。

## 1. 产品承诺

用户选择一台设备和一个节点，点击「保存并保护」后，该设备经本路由器访问外网的流量只能使用该出口。内核停止、重启、崩溃、启动失败、节点消失和配置切换期间，允许断网，禁止回退直连。管理界面退出不改变策略。

保护状态与联网状态分开。保护可以正常工作，而设备因内核停止处于断网状态。只有明确执行「解除保护并恢复普通规则」才能撤销此承诺；普通的停止、重启、暂停联网和更新操作都不解除保护。

首版只支持固定节点，不支持任意策略组。当前 ARM64/fw3 环境只能确认 IPv4 TCP 接管，因此首版应代理 IPv4 TCP，并提供独立的受保护 DNS；其他外网 UDP、IPv6 和无法代理的协议全部阻断。界面必须显示此范围，不能把“不会直连”宣传成“所有协议都可用”。后续具备 TPROXY 能力并通过验收后，再开放 UDP 代理。

保证范围是经本路由器、可识别的设备流量。设备改用另一网关、轮换 MAC 并取得新 IP、借用 LAN 内其他机器的代理等，不属于单台路由器按 MAC/IP 识别能绝对防止的情况。若需要对抗这些绕过，应配独立 SSID/VLAN 和默认禁止直出的网络策略。

## 3. 信息架构与页面

仅在 OpenWrt 界面左侧新增「设备」，保留 LuCI 内嵌导航。设置 → 网络中的原「设备访问控制」增加前往本页的入口，原有普通接管名单仍可使用。

页面从上到下：

1. 标题「设备」，说明「指定外网出口，代理不可用时保持断网」。右侧「添加设备」。
2. 独立的保护状态与内核状态：例如「断网保护已验证 · 3 台设备」和「内核已停止 · 受保护设备保持断网」。
3. 筛选「已保护 / 全部设备」及名称、IP、MAC 搜索。
4. 列表包含设备身份、固定出口、联网状态和操作。桌面用四列表格，手机变为逐设备卡片。
5. 协议范围常驻简短说明：「IPv4 TCP 与受保护 DNS 经指定节点；未支持的 UDP / IPv6 外网阻断。」

设备显示主机名、当前 IPv4、固定 IP 状态。MAC 与绑定 IP 在详情中完整显示。在线/离线只是设备发现结果，不能作为保护是否生效的证据。

未设置策略的设备显示「普通规则」，按钮「设置出口」。设备行不要放一个含义不清的开关；受保护设备的菜单只有「暂停联网 / 恢复联网」「查看诊断」「解除保护…」。

## 4. 添加与编辑流程

采用同页右侧抽屉，手机为全屏 sheet；底部操作固定。三个步骤：

### 选择设备

- 合并 DHCP 租约、静态租约、邻居表，按接口和 MAC 去重；可搜索名称/IP/MAC，支持离线设备及手动输入。
- 展示当前 IP、MAC、在线状态、地址是否固定，重复设备直接进入现有策略。
- 首版要求 MAC + 预期 IPv4 同时匹配。保护按 MAC 或保留 IP 覆盖，允许进入专属出口时则要求两者都匹配；IP 改变时保持阻断。
- 动态地址提供「为此设备固定当前 IP」的显式选项，检查冲突后创建 DHCP 静态租约。创建静态租约不代表客户端已经换用该地址；实际地址不符继续阻断，并提示重新连接网络。
- 本地管理位只能说明 MAC 可能是私有地址，不能直接断言它会轮换。提示用户确认当前 Wi-Fi 的 MAC 固定，不能一律要求关闭稳定的私有地址。
- MAC 或网段识别不可靠、没有 IPv6 阻断能力、存在地址冲突时，禁止进入“已保护”状态，并解释缺少的条件。

### 选择出口

- 只列出当前配置真实可用的固定节点，显示名称、订阅来源、协议、最近延迟；搜索不丢失当前选择。
- `DIRECT`、重命名的 direct/compatible、绕过/规则转发适配器不能选择。任意策略组首版不开放，避免嵌套、动态 provider 或空组导致直连。
- 绑定保存来源配置、provider 身份及节点身份，不能只保存展示名。名称相同但端点/协议变化时，先阻断，要求用户确认重新绑定；解析得到的 IP 正常轮换不等于节点身份变化。
- 节点不在线可以保存，界面说明“策略保留，当前可能无法联网”。延迟超时不能自动切换 DIRECT 或其他节点。
- 配置切换或订阅更新不自动选择另一个同名节点。未来的策略组模式需要完整的无直连路径验证、动态成员检查和空组 REJECT，另行设计。

### 确认保护

显示设备 → 所选节点、协议范围，以及：

> 内核停止、重启或出口不可用时，这台设备将断网。路由器管理和允许的局域网服务仍可访问。保护会保留到你明确解除。

按钮「保存并保护」。一次完成持久化和应用，不拆成容易误解的“保存 / 应用”。应用时显示“安装保护 → 应用出口 → 验证规则”，验证完成前不显示成功绿标。内核已停止时允许保存保护，结果明确为「已保护 · 等待内核启动」，不会擅自启动内核。

修改节点时先阻断该设备、关闭该设备现有连接，再切换到新出口；不能让旧连接继续使用原节点。其他设备尽量不受影响；如果核心 reload 必然影响其他连接，应在提交前显示实际影响范围。

## 5. 状态与动作

| 保护状态 | 联网状态 | 文案与动作 |
| --- | --- | --- |
| 未设置 | 普通规则 | 「设置出口」 |
| 已验证 | 出口已加载 | 「仅经 东京 02」；单独显示观测出口 IP 和验证时间，未探测时不声称已验证公网出口 |
| 已验证 | 内核停止/重启/崩溃 | 「已阻断 · 内核未运行」；重启期间保护保持在位 |
| 已验证 | 手动暂停 | 「已暂停联网 · 保护保留」；按钮「恢复联网」 |
| 已验证 | 节点缺失/身份变化/端口冲突/应用失败 | 「已阻断 · 原因」；按钮「修改出口 / 重试」 |
| 已验证 | 出口探测失败 | 「出口探测失败 · 不会回退直连」；保持绑定，不因为探测失败放行普通规则 |
| 已验证 | 设备离线 | 「设备离线 · 策略保留」；不误报为节点健康 |
| 未知 | 未知 | 管理连接中断后取消旧绿标，显示最后观测时间；不能把“无法查询”显示成已阻断或已保护 |
| 异常 | 无法保证 | 红色「保护异常，可能存在直连路径」；展示修复入口，只有紧急阻断安装成功后才可称“已阻断” |

暂停联网不需要额外确认，因为它只收紧权限。恢复联网只恢复设备策略；若内核仍停止，继续阻断并提供独立的「启动内核」。

解除保护弹窗：

> 解除 MacBook-Pro 的保护？这台设备将恢复普通上网规则，内核停止时可能直接使用宽带出口。

按钮「保留保护」「解除保护并恢复普通规则」。不使用“暂停保护”或没有说明的“删除”按钮。解除后可保留设备记录，状态回到「普通规则」。

## 6. 必须成立的实现边界

### 6.1 独立持久防火墙保护

- 新增体积很小的 `clashcube-guard` 包，包含独立 boot/init、缓存规则、恢复逻辑和升级保留列表；生成器复用现有 Go 程序，不额外安装一份大型 Go 守护进程。
- core/web 依赖 guard，升级 core、停止 supervisor、`Cleanup`、配置事务 Pause 和 dnsmasq 恢复都不能移除它。核心卸载后 guard 仍保留，解除需单独明确操作。完整卸载 guard 的后果必须写明。
- guard 在网络开始转发前装入。恢复策略失败时，使用上次有效规则或覆盖受保护范围的紧急拒绝策略；若两者都做不到，不能继续开启该范围的 WAN 转发。没有可解释的安全默认值时不放行。
- 推荐使用独立 `inet clashcube_guard` nft 表；即使固件用 fw3，也可在具备 nft 内核能力时单独安装 guard。当前容器虽然有 nft 命令，但命令存在并不证明所需 hook/表达式和固件重载流程可用，必须实测。
- 若只有 iptables/ip6tables，就需要证明独立链、IPv6、重载和启动顺序不会产生放行窗口；没有证据时界面不开放严格保护。不能靠每秒轮询补规则来承诺“不会短暂直连”。
- 规则必须早于通用 ESTABLISHED/RELATED 放行；既有直连 conntrack、软件/硬件 flow offload 也必须处理。不能只拦新连接。无法可靠关闭或逐出加速流时，阻止启用并说明原因。
- 所有无法进入专属出口的外网转发默认 DROP，包括 TCP、UDP、ICMP 与 IPv6。真实本地网段/路由器服务按最小范围允许，不把全部 RFC1918、全部 INPUT 或所有路由器代理端口当作 LAN 例外。
- 允许流量进入本机时，核验其专属 listener/策略标记；不能让普通 redir、mixed、SOCKS、其他 DNAT 路径接走后按全局 DIRECT 出网。

### 6.2 出口接管

- 每个设备策略使用受控的专属 listener 和稳定端口分配，`proxy` 固定到经验证的节点；同节点的底层能力可复用，但逻辑策略 ID、连接归属不能混淆。
- 设备入口要求接口、MAC、预期 IP 一致；专属策略优先于普通黑白名单、绕过、用户规则和全局模式。普通接管不再重复接走该设备。
- 固定 listener 的 SpecialProxy 不受 rule/global/direct 模式影响。节点不存在不替换成 DIRECT，不把端口转给普通默认入口。
- 不支持的 UDP、IPv6 在 guard 层拒绝。IPv6 不能仅靠禁 AAAA 响应来处理，客户端可能缓存地址或使用字面量。
- 后续如共享核心不足以证明受保护流量不会经其他本机服务转发，需进一步隔离入口或进程/网络命名空间；不能直接照搬 PassWall2 的全路由器 OUTPUT deny，影响未受保护设备和路由器正常服务。

### 6.3 DNS 是保护的一部分

当前 dnsmasq 公网查询来自路由器自身，设备 MAC 的 FORWARD 规则不会约束它。内核停止后恢复 dnsmasq 普通上游，会让受保护设备的查询直出。这条路径必须单独修复。

- 受保护设备 UDP/TCP 53 进入专属 DNS 路径，公网解析经所选出口；即使目的地址写成路由器，也不能转给共享公网解析回退。
- 可复用现有 Go/mihomo 能力或实现轻量 DNS relay，缓存按出口隔离，通过同一固定出口的私有代理入口连接上游。选型需在实现前用真实 mihomo 能力验证；不能假设其全局 DNS 天然支持每设备不同节点。
- 本地 hosts、DHCP 名称可由本地数据回答；公网域名不能在失败时转给共享 dnsmasq。内核停止或暂停联网时，只保留约定的本地回答，公网解析失败。
- 节点主机名 bootstrap 与设备公网域名解析分开，只允许必要的控制面解析，不把保护错误地等同于“整台路由器绝无直连流量”。DoH/DoT 应用流量也进入同一固定出口；未支持的 QUIC 路径拒绝。

### 6.4 持久化与事务

持久设备策略包含：ID、名称、接口/MAC/预期 IPv4、固定节点的来源与身份、`online/paused` 意图、配置版本。保护是绑定存在时的不变量，不能用一个通用 enabled=false 隐式取消。

新增策略的顺序：验证输入 → 保存可恢复的阻断意图并安装阻断 → 清理该设备旧直连与加速流 → 安装/验证固定出口及 DNS → 允许专属入口 → 报告结果。只有全部相关路径收敛后，操作才返回“已保护”。

任何中途崩溃，都能从已保存的阻断意图恢复。不能“先成功返回，再异步补规则”。保存新策略成功而出口应用失败时，保留新设备的阻断状态，允许重试；不能为恢复联网自动撤掉刚安装的保护。编辑失败时可回到上次安全出口，或者保持阻断。

删除/解除时反向处理，但删除保护只发生在明确的解除事务；保护与配置缓存版本不一致时先进入阻断。配置热更新、订阅更新、普通名单和自定义 listener 都必须经过同一策略验证，不能留下旁路。

后端建议提供 Devices 列表、可选出口、策略 Apply/Pause/Resume/Release、实际保护快照、受保护出口 Probe 和有界诊断事件。写请求带 revision，防止并发页面以旧配置覆盖新策略；跨进程操作串行化。网页不传 shell 命令、文件路径或自定义防火墙文本。

## 7. 验收与交付顺序

先做保护与失败路径，再连接 UI。所有安全状态以规则结构、入口归属和策略版本为依据；一次 TCP 端口连通或延迟成功不足以证明保护生效。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 正常节点出口 | 被保护设备的 TCP/DNS 使用指定节点；控制设备维持原行为 |
| stop/restart/kill -9/启动失败/管理服务升级 | 连续发起新连接和维持旧连接，结果只允许所选出口或失败，不出现宽带直出 |
| 内核包在线升级 | guard 持续存在；已停止的内核升级后仍停止；启动成功后恢复指定出口 |
| 切换 rule/global/direct、设置绕过名单 | 受保护设备出口不改变 |
| 节点缺失、同名节点替换、空 provider、DIRECT 改名 | 保持阻断，UI 给出具体原因 |
| firewall reload/restart、整机重启、外部存储缺失 | 网络启用到核心恢复的全过程均无直连窗口 |
| UDP/QUIC、IPv6 字面地址、ICMP、TCP/UDP 53 | 已支持的流量经出口，其余拒绝；观察 WAN 抓包，DNS 不能直出 |
| 既有直连长连接、软件/硬件 offload | 启用完成后旧直连停止；不因通用已建立状态而放行 |
| 设备改 IP、DHCP 续租、MAC/IP 冲突 | 不默默绑定另一设备，未知身份不自动进入普通代理入口 |
| 访问本机普通 mixed/SOCKS 或其他本机转发服务 | 不借这些入口回退到全局 DIRECT |
| 保存失败、断电、并发写、guard 缺失/损坏 | 回到旧安全策略或阻断；不能展示虚假的已保护状态 |
| 暂停/恢复/解除 | 暂停保持断网保护，恢复不擅自启动核心，只有明确解除恢复普通规则 |
| UI：1440/390、亮/暗色、键盘、长名称、失联 | 无横向溢出；焦点和操作可达；失联不保留旧绿标；错误保留草稿 |

Docker 通过后，仍需在目标路由器验证内核模块、桥接拓扑、无线 MAC 可见性、offload、启动和固件重载。未完成前不能宣称真机已满足不直连保证。
